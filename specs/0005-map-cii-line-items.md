## Context

Invoice lines (BG-25) are what users check most often against the PDF:
quantities, prices, VAT rates. They extend the field model from 0004 and must
stay readable for invoices with many lines.

## Requirement

Given a CII invoice, the field model additionally contains one section per
invoice line, in document order (not sorted by line ID), placed after
"Käufer (BG-7)" and before "Zahlung (BG-16)". Each line section uses the same
field structure and display rules as 0004 (amounts, codes), plus:

- **Quantities** (BT-129) are shown with German decimal separator, trailing
  zeros removed, followed by the unit name and code (`8 Stunden (HUR)`); for
  unit codes without a known name only the code is shown (`2,5 XPP`).
- **VAT category** (BT-151) is shown as `<name> (<code>)` like BT-118.

## Contracts (optional)

Line section title: `Position <BT-126>` (e.g. `Position 1`). Fields in this
order: BT-126, BT-127 (repeatable), BT-153, BT-154, BT-155, BT-129, BT-130,
BT-146, BT-149, BT-131, BT-151, BT-152, BT-128, BT-133.

Units with a German name: `C62` Stück, `H87` Stück, `HUR` Stunden, `DAY`
Tage, `MON` Monate, `KGM` Kilogramm, `MTR` Meter, `LTR` Liter, `LS` pauschal.

## Acceptance criteria

All sample invoices are defined in [fixtures.md](../docs/fixtures.md).

- [ ] Given CII sample A, when it is mapped, then the model contains sections
      `Position 1` and `Position 2`, in that order, between "Käufer (BG-7)"
      and "Zahlung (BG-16)".
- [ ] Given CII sample A, then `Position 1` contains BT-153 `Beratung`, BT-129
      display `8 Stunden (HUR)`, BT-146 display `125,00 EUR`, BT-131 display
      `1.000,00 EUR`, BT-151 display `Normalsatz (S)`, BT-152 `19`; and
      `Position 2` contains BT-129 display `2 Stück (C62)`.
- [ ] Given CII sample B, then `Position 1` contains two BT-127 fields
      `Lieferung KW 46` and `inkl. Anfahrt` in document order, and
      `Position 2` contains BT-151 display `Steuerbefreit (E)`.
- [ ] Given sample A with these values in line 1, the display is:

      | element | raw | display |
      |---|---|---|
      | BT-129 + BT-130 | `2.500` `KGM` | `2,5 Kilogramm (KGM)` |
      | BT-129 + BT-130 | `2.5` `XPP` | `2,5 XPP` |
      | BT-129 + BT-130 | `-2` `C62` | `-2 Stück (C62)` |
      | BT-146 | `12.3456` | `12,3456 EUR` |

- [ ] Given sample A with line IDs `A1` and `A2` (in this document order),
      then the sections are titled `Position A1` and `Position A2`; given line
      IDs `10` and `2` in this document order, then the sections are
      `Position 10`, `Position 2` (document order is kept).
- [ ] Given CII sample L, when it is mapped, then the model contains 500 line
      sections and mapping takes less than 1 s on the reference machine (see
      [requirements](../docs/requirements.md)).
- [ ] The `location` of BT-131 in `Position 2` of sample A selects the line net
      amount element of the second line and no other element.

## Out of scope

- Line-level allowances and charges (BG-27, BG-28), item attributes (BG-32),
  sub-lines of the Extended profile.
- UBL lines (0006).

## Progress

- **Done** — line items mapped in `crates/core/src/fields/cii.rs`
  (`LINE_SECTIONS`); section titles with the line ID, values from attributes
  (BT-130) and quantity display with unit names in `fields/mod.rs` and
  `fields/display.rs`. Field locations now reuse the section's location,
  which removed quadratic work for many lines. 9 tests in
  `crates/core/tests/map_cii_lines.rs`; sample L generated by
  `sample_l_cii` (noted in docs/fixtures.md). No new dependency.
- **Verified** — 2026-11-16: `cargo test --workspace` 52 passed (9 new);
  sample L maps in about 106 ms (debug) / 12 ms (release);
  `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D
  warnings` and architecture check clean. Manual smoke run on two real
  Factur-X invoices.
